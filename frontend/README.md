# DOOMSDAY · интерфейс контроля качества

Четыре раздела для реестра диалогов, настройки чек-листа, пересмотра оценок и аналитики. FastAPI раздаёт `frontend/public/` и HTTP API на одном адресе. Интерфейс написан на HTML, CSS и JavaScript без отдельной сборки.

## Запуск

Из корня репозитория в Windows PowerShell, Python 3.11 или новее:

```powershell
py -3 -m venv backend/.venv
& .\backend\.venv\Scripts\python.exe -m pip install -r requirements-backend.txt -e .
& .\backend\.venv\Scripts\python.exe -m backend --host 127.0.0.1 --port 8000
```

Откройте [127.0.0.1:8000](http://127.0.0.1:8000/). Для Linux команды установки и запуска есть в [README бэкенда](../backend/README.md).

- Загрузите DEV или контрольную выгрузку через **Диалоги → Импорт JSON**. Если положить DEV в `codex_context/data/dev.json`, FastAPI импортирует его при старте. Повторный импорт идентичных записей пропускает дубликаты.
- Перед запуском оценки задайте параметры модели в окружении процесса FastAPI по [инструкции оценщика](../CQA_README.md#подключение-модели). Когда модель недоступна, карточка показывает причину. Импорт, просмотр, чек-листы и сохранённые результаты доступны независимо от подключения модели.
- Для проверки интерфейса без DEV можно импортировать `codex_context/eval/synthetic_dialogue.json`. Он помечен как тестовый. При штатном запуске API возвращает только сохранённые результаты и ответы подключённого оценщика.

## Сценарий для жюри

1. Импортируйте JSON и найдите диалог в реестре. Выберите текущую версию чек-листа и нажмите **Оценить**. Карточка сама проверит статус задания.
2. Откройте доказательство или проверенный участок в результате. Исходные реплики выделятся в транскрипте. Если доступна запись, прослушайте её в плеере. Кнопка перемотки появляется только у реплик с явным смещением в записи.
3. Из карточки перейдите в чек-листы, измените критерий или добавьте новый, сохраните версию и вернитесь к диалогу. Запустите оценку с новой версией. Предыдущий результат доступен в истории.
4. Подайте апелляцию по одному из критериев. В очереди можно подтвердить оценку или указать новый ответ, объяснение и доказательства. После сохранения сравните исходный и итоговый результат и откройте историю.
5. В аналитике отфильтруйте язык, канал или грубые ошибки. Показатели основаны на последней оценке каждого диалога. В распределение входят только числовые итоги, включая нулевые. Тестовые записи, помеченные в API, можно исключить из выборки.

## Проверки и интеграция

```powershell
npm.cmd --prefix frontend test
& .\backend\.venv\Scripts\python.exe -m unittest discover -s backend/tests -v
```

Тесты frontend используют встроенный runner Node.js 22+. HTTP-клиент находится в `public/api.js`. Поиск по ID, фильтры и аналитика используют сводки диалогов из всех страниц API. Транскрипт загружается только при открытии карточки или формы пересмотра. Снимки чек-листов, версии, оценивание и пересчёт апелляций остаются на сервере. [Статус проверок](STATUS.md).
