## Функции и доказательства

| Требование | Реализация и проверка | Граница подтверждения |
|---|---|---|
| RU/KZ/EN; оценка оператора в контексте client/bot/system | `data.py` сохраняет все роли, порядок, timestamps и индексы; `prepare_request` передаёт весь транскрипт и язык. Исторический реальный DEV-прогон содержит все три языка | Поддержка входа и реальные вызовы подтверждены; смысловое совпадение с GT не измерено |
| Редактор критериев, формулировок, типов и весов | `frontend/public/checklists.js`, `checklist-model.js`; сервер сохраняет новую версию и проверяет конфигурацию | Добавление критерия с применением реально проверено через браузер и модель; отдельные поля редактора подтверждены кодом и тестами, а не все отдельным live-прогоном |
| Числовые шкалы и доступность N/A | UI редактирует `scale_max`, ступени/описания, `na_allowed`, `na_rule`; payload строит допустимые ответы. Общий validator отклоняет неполные или некорректные настройки | Проверена конфигурационная логика; это не доказательство верного определения N/A моделью |
| Изменённый критерий применяется к новой оценке | Реальный браузерный сценарий: v1/8 критериев → отдельная v2/9 → новый модельный ответ с девятым критерием | Тестовый дополнительный критерий и публичный синтетический диалог, не скрытый контрольный набор |
| Ответы, обоснования, evidence и checked_range | Общий validator проверяет ID и порядок диапазона; UI выделяет исходные сообщения. Реальный переход к evidence выполнен | Существование ссылки не доказывает смысловую обоснованность; её проверяют отдельно |
| Звонок и запись | UI содержит аудиоплеер, не скачивает звук заранее; обработка оценки использует выданный транскрипт | Доступность внешних audio URL зависит от срока ссылки. ISO timestamp не выдается за позицию в записи; без явных offsets точный seek не заявляется |
| Веса, шкалы, N/A, отдельный critical flag | Один Decimal-scorer, глобальное перераспределение N/A, финальное округление. Flag не входит в сумму и не обнуляет её | Формула и значения проверяются тестами и повторным расчётом; scorer не устанавливает правильность исходных ответов ИИ |
| Апелляция, решение, исходный и финальный результат | UI отправляет апелляцию и решение; backend хранит ревизии и снимок чек-листа. Реальное подтверждение апелляции и сохранение оригинала проверены | Отдельный синтетический UI-тест `change` подтвердил 100 → 92,31, сохранение оригинала и reload; это инженерный пересмотр, не GT |
| Сохранение после перезапуска | Браузерная проверка после настоящего рестарта backend: обе оценки, апелляция и две версии чек-листа сохранились | GET-only проверка, без нового модельного вызова |
| Официальный экспорт | `export-results`, `submission.py`, packaged JSON Schema, строгая исходная восьмикритериальная конфигурация | Схема пакета — инженерная формализация PDF, не отдельно выданная машинная схема организаторов |
| Открытый Git и результаты до стоп-кода | Требуются commit **и** push файлов сдачи; публикацию проверять по SHA и наличию файла в ветке | Локальный файл или открытый PR сами по себе не означают, что новые изменения опубликованы или находятся в main |

## Что не объявляется подтверждённым

- Независимых human-reviewed меток нет; accuracy/MAE относительно эталона
  отсутствуют. Доля успешной обработки не является точностью.
- Известные смысловые ошибки и границы голосового регламента сохраняются в
  [AI_QUALITY_REVIEW.md](AI_QUALITY_REVIEW.md). Смысловой кандидат не активируется
  только ради технической сдачи.
- Выключенный GPU не готов к новым оценкам. Просмотр сохранённых данных,
  апелляции и редактирование доступны локально; новый inference требует
  работающей модели и SSH-туннеля. `/api/health=ready` проверяет настройки,
  успешный синтетический запрос — фактическую доступность модели.
- До появления настоящего PROD и публикации его файла контрольная сдача
  не завершена. До подтверждённого времени демо нельзя обещать доступность
  сервера на неопределённый срок.
